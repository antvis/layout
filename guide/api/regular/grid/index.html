#Grid LayoutNon-Iterative

Arrange nodes in a regular grid. Great for stable, predictable structures like matrix views or card lists.

#When to use

  • Regular placement with predictable positions
  • Control density via rows/cols

#Input requirements

  • Nodes must have unique id

#Usage

import { GridLayout } from '@antv/layout';

const layout = new GridLayout({ width: 800, height: 600, rows: 8, cols: 10 });
await layout.execute(data);

#Options

#Common options

These options apply to all layouts and define the reference size, center, worker usage, and field mappings.

OptionDescriptionTypeDefault
width / heightReference size. Many layouts derive default centers/scales.numberundefined
centerLayout center. 2D uses [x, y], 3D uses [x, y, z].[number, number] | [number, number, number]undefined (layout-dependent)
enableWorkerRun in a Web Worker when available; fallback to main thread.booleanfalse/undefined (layout-dependent)
nodeNode field mapping for business data.(datum) => ({ id?, x?, y?, z?, parentId?, isCombo? })undefined
edgeEdge field mapping for business data.(datum) => ({ id?, source?, target? })undefined

#Node mapping fields

  • id: unique node id, required.
  • x/y/z: optional initial coordinates for warm start or continuous layouts.
  • parentId: parent combo id for composite or nested layouts.
  • isCombo: whether this is a combo node.

#Edge mapping fields

  • source / target: endpoint node ids, required. Must match some node id.
  • id: optional edge id. Auto-generated if omitted.
